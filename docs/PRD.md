# YouTubeLocalSubtitles 产品需求

版本：0.1 草案

日期：2026-11-10

状态：需求基线；实现已进入开发预览，实际完成情况见 [验证记录](VERIFICATION.md)。文中的性能门槛仍是待验收目标。

**0.2.0 变更**：根据播放卡顿和字幕错位反馈，默认改为提前读取公开音轨，在后台生成带媒体时间的字幕缓存。原视频不为字幕暂停、回退或改速；字幕严格按当前媒体时间显示。首次可有后台准备间隔，但不再把迟到结果显示到后面的画面上。下文首次设计的标签页采集仅保留为明确标注延迟的兼容方式，不再是默认入口。

## 1. 产品目标

观看 YouTube 时，如果视频没有可用字幕，用户可以直接在播放器旁开启本地字幕。音频在本机识别，按需翻译成中文，字幕叠加在播放器内。

用户可以选择“英文”“中文”“双语”。视频已有可用字幕时，默认使用 YouTube 自身的字幕能力，不自动启动本地识别。

本项目优先保证观看过程可用：原视频声音正常、字幕不会因翻译而无限积压、拖动进度后不会显示上一段内容。

## 2. 已确认需求与设计默认值

| 项目 | 内容 | 依据 |
| --- | --- | --- |
| 部署位置 | `E:\GitHub\YouTubeLocalSubtitles` | 用户明确指定 E 盘 GitHub 文件夹 |
| 代码仓库 | GitHub 同名公开仓库 | 用户明确要求 |
| 识别方式 | 本地模型，不固定必须用 Qwen | 用户明确允许其他模型 |
| 默认启停 | 没字幕时补字幕；有字幕时默认不开本地识别 | 用户明确要求 |
| 显示模式 | 用户可选英文、中文、双语 | 用户明确要求 |
| 操作入口 | 播放器旁按钮，避免依赖难找的工具栏图标 | 用户最新要求 |
| 捕获授权 | 接受 Chrome 官方交互式授权；页面按钮优先，保留快捷键入口 | 用户接受官方捕获方案，随后要求页面按钮 |
| 首期语言 | 以英语音轨作为第一版验收范围 | 设计默认值；其他语言暂不承诺 |
| 首期场景 | 普通 YouTube 点播页 | 设计默认值 |
| 默认模式 | 双语，用户选择后记住设置 | 可调整的设计默认值 |
| 自动生成字幕 | 视为已有字幕，不自动启用本地识别 | 对“已有字幕”的设计定义 |

“有字幕”是指存在可用字幕轨道，与 CC 按钮当前是否打开无关。“字幕轨道状态未知”不等于“没有字幕”。

## 3. 第一版范围

### 必须完成（P0）

1. Chrome 扩展，在普通 YouTube 播放器旁显示“本地字幕”按钮。
2. 检测原生字幕轨道，包括人工字幕与自动生成字幕。
3. 明确区分“检测中 / 已有字幕 / 无字幕 / 无法判断”。
4. 用户从页面按钮启动捕获会话；按 Chrome 要求完成当前标签页音频共享。
5. 会话内只有满足识别条件时才向本地服务发送音频并执行推理。
6. 支持英文、中文、双语切换，设置在本机持久保存。
7. 英文语音识别与英译中均在本机完成。
8. 支持开始、停止、手动强制开启；能够显示服务未运行、模型加载、共享取消等状态。
9. 正常播放声音，处理暂停、恢复、进度跳转、切换视频和广告。
10. 提供本地服务启动/停止方式、扩展加载说明和必要的运行诊断。

### 后续增强（P1）

- 字体大小、字幕位置与背景透明度调整。
- SRT / 双语字幕导出、用户主动保存历史。
- 更多源语言、术语表、站点或频道偏好。
- 更细的时间戳对齐、模型对比与可配置模型。
- 安装器、托盘入口、按需自启动服务。

### 第一版不包含

- YouTube Shorts、直播、画中画、嵌入第三方网站的播放器、手机浏览器。
- 自动下载完整视频或音轨来生成整片字幕。
- 视频画面 OCR；检测烧录在画面里的字幕。
- 在已有原生字幕时，默认抓取并翻译原字幕。
- 云端识别/翻译、账号登录、上传观看记录。
- 无需任何授权就捕获所有新标签页的音频。

## 4. 页面交互

### 4.1 页面入口

入口位于普通播放器附近，文案为“本地字幕”。全屏时提供播放器内可触达的同一功能入口，不依赖页面外工具栏。

无会话时，按钮可展开小面板：

```text
本地字幕
原生字幕：无可用字幕 / 已有字幕 / 检测中 / 无法判断
显示方式：[英文] [中文] [双语]
[开始本地字幕]
```

有原生字幕时显示“视频已有字幕，默认使用 YouTube 字幕”，提供次级操作“仍然使用本地识别”。不自动切换 YouTube 的 CC 开关。

开始后显示简短运行状态与“停止”。用户主动开始后才显示共享提示和模型加载状态，普通观看时不反复弹窗。

### 4.2 首次启动流程

1. 本地服务已启动；首次使用在扩展设置页完成本机配对。
2. 打开英语视频，点击页面内“本地字幕”。
3. 无字幕时点击开始；有字幕时需要明确选择强制开启。
4. 页面按钮方案使用 Chrome 共享选择框，用户选择当前 YouTube 标签页并开启音频共享。
5. 若选择了其他标签页、没有共享音频或取消，提示原因并保持停止，不回退成系统麦克风录音。
6. 模型准备完成后生成字幕。英文模式只运行识别；中文/双语模式运行识别与翻译。

页面按钮不等同于 Chrome 的扩展调用授权，因此不承诺直接调用 `tabCapture` 后无弹窗开始。主入口的捕获闭环必须在技术原型阶段验证；快捷键/扩展操作入口使用 `tabCapture` 作为备用路径。[Chrome 捕获说明](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture)、[activeTab 授权说明](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

### 4.3 会话内自动判断

“自动”指已由用户启动的有效捕获会话内自动启停识别，不指网页加载后静默捕获音频。

| 条件 | 行为 |
| --- | --- |
| 无捕获授权，视频无字幕 | 显示页面入口，等待用户启动 |
| 会话有效，确认无字幕，正文播放中 | 运行本地识别；按显示模式决定是否翻译 |
| 有可用原生字幕 | 停止本地推理、清除本地字幕；强制模式除外 |
| 字幕状态未知或仍在检测 | 暂停自动识别，保留手动强制开启 |
| 正在播放广告 | 停止向模型提交音频，不生成广告字幕 |
| 视频暂停、缓冲或结束 | 暂停提交音频，不持续识别静音 |
| 拖动进度、切换视频、倍速变化 | 丢弃旧缓冲及旧结果，重新建立时间映射 |
| 用户停止或 Chrome 停止共享 | 释放捕获轨道、清空缓冲、停止该会话 |

为保留会话内自动恢复能力，暂停推理时允许保留已获授权的捕获流；不发送音频到识别服务，不保存音频，并保留 Chrome 的共享指示。用户点击“停止”必须真正释放捕获。若流已被释放，下次启动仍可能需要共享选择框。

页面完整刷新或离开页面后，不保证保留页面按钮方案的会话；需重新授权。YouTube 站内切换视频时尽可能保留流，但必须重新判断字幕。

## 5. 字幕显示规则

| 模式 | 输出 | 推理行为 |
| --- | --- | --- |
| 英文 | 英语识别文本 | 识别；不加载或调用翻译模型 |
| 中文 | 中文译文 | 识别后翻译；等待时显示轻量状态，不伪装成已有译文 |
| 双语 | 英文在上、中文在下 | 英文先显示，对应中文完成后补上 |

- 切换模式不重新获取音频权限；优先复用当前会话已有文本。
- 英文切到中文/双语时允许加载翻译模型，但不得清空识别状态。
- 切回英文应取消不必要的翻译排队任务；已运行任务的结果可丢弃。
- 不为无限久以前的字幕补翻译。失效、超时或过旧译文不覆盖当前句。
- 本地字幕支持普通窗口与网页/浏览器全屏；不遮挡主要控制按钮。
- 强制识别时如需隐藏原生字幕，只临时影响当前会话并在停止后恢复；不修改全局字幕偏好。
- 第一版处理英语输入；非英语内容检测到后提示“该语言尚未完成验证”，不把非英语识别文本冒充英文。

## 6. 性能与质量目标

以下均为设计门槛，必须实测后决定能否达到。不能把模型发布方的服务器吞吐数字当作本机延迟。

参考硬件等级：现代 Windows 笔记本、32GB 内存、8GB NVIDIA 独显；公开文档不保存个人设备标识。

| 指标 | 初始目标 / 判断方式 |
| --- | --- |
| 实时处理能力 | 1 倍速连续 20 分钟不持续积压；分段识别耗时 / 音频时长 P95 < 0.8 |
| 英文字幕延迟 | 预热后，字幕段对应语音结束至首次显示 P50 ≤ 3 秒、P95 ≤ 6 秒 |
| 中文额外延迟 | 对应识别结果就绪至译文显示 P50 ≤ 2 秒、P95 ≤ 4 秒 |
| 总体延迟统计 | 同时记录整段语音起点至显示的延迟；分段等待不应被统计口径隐藏 |
| 资源预算 | 识别与翻译服务峰值 RAM 合计目标 ≤ 8GB；翻译 VRAM 目标 ≤ 5GB，给 Chrome 留出余量 |
| 清晰英语质量 | 自建清晰口语样本集至少 20 分钟，规范化后 WER 目标 ≤ 15% |
| 翻译质量 | 至少 50 个已核对英语片段人工检查；至少 45 个保留主旨，无明显漏译/反义；单独统计人名、数字、术语错误 |
| 播放体验 | 无持续静音、回声、音频双重播放、明显卡顿 |
| 倍速 | 1 倍速为正式验收；1.25/1.5 倍速记录结果；2 倍速不承诺实时 |

模型首次加载时间与预热后的延迟分别记录。噪声、多人重叠、音乐、口音等样本单列，不混入清晰英语的质量指标来掩盖问题。

## 7. 隐私与本地运行

- 安装期间允许下载依赖、运行时和模型；运行识别/翻译时不调用外部 AI 接口。
- 仅处理用户选择的标签页音频，不启用麦克风，不监听整个系统声音。
- 默认不落盘音频、完整字幕、视频 URL 或标题。诊断日志只记录错误、状态、耗时和资源指标。
- 本地服务只监听回环地址，访问需配对令牌。仓库不包含令牌、个人配置、模型权重和测试录音。
- 不自动安装扩展、修改 Chrome 个人配置、开启远程调试或配置开机启动。

## 8. 验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 人工字幕存在，但 CC 被关掉 | 仍判断为已有字幕，默认没有本地推理请求 |
| A02 | 只有 YouTube 自动生成字幕 | 同 A01 |
| A03 | 确认无字幕的英语视频 | 从页面入口授权后能显示本地字幕 |
| A04 | 英文/中文/双语来回切换 | 显示正确；英文模式不继续排队翻译 |
| A05 | 取消共享、关闭音频共享或选错标签页 | 清楚提示，不误录其他音源 |
| A06 | 授权会话内切到有字幕视频，再切到无字幕视频 | 自动停推理/恢复；流若失效则提示重新共享 |
| A07 | 快进、倒退、换视频、切倍速 | 老句与老译文不会出现在新位置 |
| A08 | 广告、暂停、缓冲、结束 | 不生成广告或静音幻觉字幕；恢复正文后继续 |
| A09 | 全屏和退出全屏 | 字幕及停止入口均可见，布局不溢出 |
| A10 | 服务未启动、模型缺失、显存不足、翻译超时 | 显示可操作原因；原视频继续播放 |
| A11 | 同时打开两个 YouTube 标签页 | 第一版只允许一个活动识别会话；切换需明确操作 |
| A12 | Chrome 停止共享、标签页关闭、扩展重载 | 释放资源，不继续接收或处理音频 |
| A13 | 20 分钟连续识别 | 达到第 6 节目标，附实测记录 |
| A14 | 无法获得可靠字幕轨道信息 | 显示未知，自动模式不误当成无字幕 |
| A15 | 非英语语音 | 给出语言范围说明，不输出标为英文的其他语言文本 |
| A16 | 已有字幕时手动强制开启后停止 | 本地字幕停止，原生字幕临时变化得到恢复 |
| A17 | 已下载模型后阻断外部网络，仅保留本机连接 | 用本地播放测试素材验证识别翻译不依赖外部 AI；真实 YouTube 播放本身仍需要网络 |

## 9. 交付与实施顺序

1. **需求文档**：本 PRD、技术方案和公开文档仓库；此阶段不下载大模型。
2. **捕获原型**：页面按钮、Chrome 选择框、当前标签页校验、持续音频、全屏入口。先验证权限和播放声音。
3. **模型基准**：英语样本对比识别方案，实测识别与翻译共同运行的速度和资源。
4. **最小闭环**：无字幕检测 → 音频 → 英文 → 中文 → 播放器叠加。
5. **稳定性与交付**：补齐状态切换、错误恢复、连续运行验证、安装与启动脚本。

未通过第 2、3 步前，不宣布技术可用或承诺具体延迟。

## 10. 尚需原型验证的事项

- 页面内按钮的共享选择框、当前标签页身份校验及 PCM 传递能否在目标 Chrome 稳定运行。
- YouTube 字幕轨道与广告状态检测在当前页面结构下的可靠性。
- Qwen INT8 CPU 分段识别与 GPU 本地翻译能否同时达到目标；不达标时比较替代模型。
- 页面按钮方案在完整刷新后是否必须重新授权；以真实浏览器测试为准。

以上是实现风险，不是尚未回答的用户需求。其余普通参数可在实现时按本文默认值推进。
