# 使用说明

适用版本：0.2.0 开发预览，Windows + Chrome，英语视频。

## 本机使用

项目位于 `E:\GitHub\YouTubeLocalSubtitles`，依赖、模型和 `dist` 已准备好。

1. 双击 `Start.cmd` 启动本地服务。
2. 在 `chrome://extensions` 开启开发者模式，加载项目中的 `dist` 文件夹。已加载过的扩展点击“重新加载 ↻”，随后刷新 YouTube。
3. 首次使用打开 [本机设置页](http://127.0.0.1:18765/setup)，点击“连接 Chrome 扩展”。
4. 在播放器右上角点击“本地字幕”，选择英文、中文或双语，点击开始。

**0.2.0 默认提前读取当前视频音轨，后台生成字幕，再按视频时间显示。普通方式不需要共享屏幕或标签页。** 原视频正常播放，程序不为字幕自动暂停、倒退或改变倍速。

首次启用仍有后台准备时间；准备好之前可能暂时没有本地字幕。程序不会把已经过期的识别结果塞到后面的画面上，也不保证冷启动立即出现第一句。

## 显示与自动判断

- 英文模式只识别英语；中文和双语模式另用本机模型翻译。
- 字幕按播放器时间显示，而不是收到识别结果就显示。暂停时字幕随画面保持，跳转后查询对应区间，迟到的译文只缓存。
- 已有可用的人工或自动字幕时默认使用 YouTube 自身字幕，不开启本地识别。关闭 CC 不等于没有字幕。
- 只有自动字幕记录、但播放器明确表示不可用且当前字幕列表为空时，允许本地识别。
- 无法判断时默认等待；确实想强制识别可勾选面板中的选项。
- 点击“停止本地字幕”会停止当前处理并清空字幕缓存。

目前按语音片段显示，尚非逐字时间对齐。英语以外的音轨和高倍速播放不在本次验证保证范围。

## 升级

本机已补齐依赖，不必重新下载模型。服务已升级后，只需在扩展管理页重新加载扩展，再刷新视频。扩展卡片应显示 **0.2.0**。

从另一份旧源码自行更新时，先运行 `Install.cmd` 补齐 PyAV 和 yt-dlp 等依赖，再用 `Stop.cmd` / `Start.cmd` 重启服务。安装器会复用已校验的模型。Chrome 可能保留旧版后台脚本，仅刷新网页不够。

安装需要 Node.js 22 或更新版本。YouTube 音轨读取还使用随安装脚本配置的本地匿名播放验证助手；其源码、依赖和缓存都位于项目的 runtime/cache 下，不需 Docker 或浏览器登录信息。

## 兼容采集

面板“兼容方式”和快捷键 `Alt + Shift + L` 保留实时标签页音频采集，字幕可能存在处理延迟，**不是默认同步方式**。这一路径需要在 Chrome 共享框选择当前标签页音频；核对目标后即释放无用的视频轨道。

默认方式读取失败时会明确提示，不会悄悄改成画面采集。需要登录、受限或部分直播视频可能无法独立读取音轨。程序不读取日常浏览器的登录 Cookie。

## 常见情况

| 情况 | 处理 |
| --- | --- |
| 仍然弹出共享框 | 确认扩展为 0.2.0，已重新加载；使用主按钮而非兼容方式或快捷键 |
| 没有页面按钮 | 确认已加载 dist，刷新普通 watch 视频页 |
| 尚未配对 | 在本机设置页连接扩展，再刷新 YouTube |
| 正在准备同步字幕 | 视频正常播放，后台正在读取音轨或加载模型；首次可能较慢 |
| 无法提前读取音轨 | 来源可能受限或网络失败，可重新开始重试；不会自动切换采集方式 |
| 某一段没有字幕 | 该段可能尚未准备好、已过期、没有语音或不在缓存中；不会用别的时间段替代 |
| 更新后异常 | 重新加载扩展并刷新视频；自行更新服务代码时再重启服务 |

## 本地与验证范围

识别和翻译都在本机运行，不调用云端 AI。默认方式从 YouTube 读取当前公开视频音频，不录麦克风、整个系统声音或屏幕。音频和字幕默认不保存为历史文件；字幕缓存位于内存，停止后清空。

`config.local.json` 含配对信息，不应公开分享。模型、缓存、虚拟环境和日志由 Git 忽略。停止服务使用 `Stop.cmd`。

本次受控 720p 测试没有自动暂停或改速；新增 938 帧中丢 2 帧，98 次可见字幕采样均处于对应区间。真实 BBC 音轨的三个区间已验证在播放时间前准备好。这不是所有视频和程序负载下都不掉帧的保证。

20 分钟真实站点连续观看、完整质量样本集及更多异常情况仍待验证。详见 [验证记录](VERIFICATION.md)。
