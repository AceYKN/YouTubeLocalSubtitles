- Windows x64，Python 3.12，Chrome for Testing 158.0.8127.18。
- 日常 Chrome 检测到版本 156.0.8078.80，未修改该浏览器配置或代为加载扩展。

- 浏览器使用独立的全新测试配置。固定重用旧配置曾导致后台脚本缓存，已改为每次使用新配置，并将“更新扩展必须重新加载”写入说明。

## 模型小样本耗时

独立模型测试使用上游包中的三个 4 秒音频片段，只统计耗时和输出是否非空，没有把结果当成正式准确率测试。

| 测试 | 实测 |
| --- | --- |
| 第一个 4 秒片段，总耗时（含模型首次加载） | 5.422 秒 |
| 第一个片段纯识别 | 0.953 秒 |
| 第二个 4 秒片段纯识别 | 1.157 秒 |
| 第三个 4 秒片段纯识别 | 1.156 秒 |
| 首次短句翻译，含模型启动 | 4.219 秒 |
| 后续短句翻译 | 0.640 秒 |

这是少量样本，不能据此计算有代表性的 P95、WER、翻译合格率或长时资源峰值。

## 浏览器字幕链路

受控页面使用 YouTube 形态的播放器与字幕元数据，注入实际交付扩展；音频为 Windows 语音合成直接写入 WAV 的原创英语短文。录制、PCM 传输、VAD、ASR 与翻译均走真实实现，没有用预写字幕替代模型输出。

最近一次完整测试：从开始共享到首次英文显示约 **10.44 秒**，到首次双语显示约 **13.89 秒**。包含语音分段等待和冷加载；不能与纯模型推理耗时混用，也不能视为预热后的稳定延迟。

该受控测试可以证明浏览器权限、Capture Handle 校验、AudioWorklet、扩展路由和模型链路共同工作，不能证明当前 YouTube 的所有页面接口和实际视频均兼容。

## 真实 YouTube 页面检查

使用未登录、独立且静音的浏览器打开真实 YouTube 普通视频页。确认“本地字幕”按钮可注入，能够读取当前播放器响应中的字幕轨道。测试页面返回两个字幕轨道，扩展默认保持本地识别关闭。

测试网络中视频媒体请求出现 403 / 连接关闭，未完成该真实视频的持续音频识别。因此真实站点端到端字幕效果不能标为验收通过。没有修改用户日常 Chrome 配置、安装扩展或重启日常浏览器来绕过测试限制。
